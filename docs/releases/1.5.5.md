Large folders open in Finder several times faster, and Google Docs, Sheets and Slides no longer show an enormous size or crash Time Machine backups. Every change in this release was written by [Mike Grupenhoff (@mgrupenhoff)](https://github.com/mgrupenhoff), who also measured each one on his own clouds. Thank you, Mike.

## Requirements

- macOS 15 or later, Apple silicon or Intel
- rclone. If none is installed, Nimbus offers to download the official build for your Mac and checks it before use. Share links and backup previews need rclone 1.76 or later.

## Install

From 1.1.0 or later: choose Nimbus > Check for Updates…, or wait for the automatic check if you turned it on.

With Homebrew: `brew trust --tap casavargas/tap && brew tap CasaVargas/tap && brew install --cask nimbus`, or `brew upgrade --cask nimbus` if you installed it that way.

From 1.0.1 or earlier: open the DMG, drag Nimbus to Applications, launch it. The app is signed with a Developer ID certificate and notarized by Apple, so Gatekeeper opens it without warnings. Nothing to redo.

## Faster

- **Opening a large folder in Finder for the first time.** Nimbus asked rclone for the whole folder again for every 500 items, and spent most of the wait reading each file's date. A folder now comes back in one piece, and dates are read about six times faster. In testing on a Nextcloud cloud, folders of about 1,000 files appeared in about 5 seconds instead of 15 to 18. Folders in the Nimbus window list faster too. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#174](https://github.com/CasaVargas/Nimbus/pull/174), [#175](https://github.com/CasaVargas/Nimbus/pull/175))
- **Downloads, uploads, renames and thumbnails in big folders.** To find one file, Nimbus listed the whole folder it is in, every time. In a folder of 5,000 files that could keep Nimbus's Finder extension at full CPU for hours, with everything else in that cloud waiting behind it. Nimbus now asks for just the one file. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#176](https://github.com/CasaVargas/Nimbus/pull/176))

## Fixed

- **Google Docs, Sheets and Slides showed an enormous size in Finder, and Time Machine backups could crash on them.** Their size isn't known until they are exported, and Nimbus now tells Finder so instead of passing on a size of 9 exabytes. Files already in Finder are corrected in the background while your Mac is idle, so it can take an hour or so after updating; a Google document you had already downloaded downloads once more. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#172](https://github.com/CasaVargas/Nimbus/issues/172), [#173](https://github.com/CasaVargas/Nimbus/pull/173))

Everything new in 1.5 is described in [the 1.5.0 release notes](https://github.com/CasaVargas/Nimbus/releases/tag/v1.5.0).

## Known issues

- Files dropped at the top level of a Backblaze B2, S3 or similar cloud fail in Transfers: they have to go inside a bucket.
- Sharing more than 2 GB of items that have to be copied first (photos from Photos, files inside another app's own storage) is refused with a message. Use Services > Send to Nimbus… in Finder for those.
- After you set up your own Google sign-in, Google shows "Google hasn't verified this app" when you sign in. That is expected for an ID you made yourself: choose Advanced, then continue.
- On a Google Drive cloud still using the shared sign-in, choosing a folder in a sheet and Send to Nimbus's check for existing names can still time out after 30 seconds. Try again, or set up your own sign-in.
- After quitting Nimbus in the middle of a backup, the next run can fail once on a leftover temporary file. Run it again and it completes.
- A backup started by hand and cut off by quitting is not marked as stopped; its row still shows the previous run.
