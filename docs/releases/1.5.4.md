Adding an iCloud Drive account works again, Finder shows full file names, files dragged from Finder onto the Nimbus window upload to the folder you're looking at, and downloads from one cloud stay safe when another is turned off. Thanks to [Mike Grupenhoff (@mgrupenhoff)](https://github.com/mgrupenhoff) for four of the fixes in this release.

This release replaces 1.5.3, which was withdrawn within the hour: it was signed without its app group, so Finder could not show your clouds. If your copy updated to 1.5.3, this update puts Finder back.

## Requirements

- macOS 15 or later, Apple silicon or Intel
- rclone. If none is installed, Nimbus offers to download the official build for your Mac and checks it before use. Share links and backup previews need rclone 1.76 or later.

## Install

From 1.1.0 or later: choose Nimbus > Check for Updates…, or wait for the automatic check if you turned it on.

With Homebrew: `brew trust --tap casavargas/tap && brew tap CasaVargas/tap && brew install --cask nimbus`, or `brew upgrade --cask nimbus` if you installed it that way.

From 1.0.1 or earlier: open the DMG, drag Nimbus to Applications, launch it. The app is signed with a Developer ID certificate and notarized by Apple, so Gatekeeper opens it without warnings. Nothing to redo.

## Fixed

- **Adding iCloud Drive failed with "Request failed (500)" before you could sign in.** rclone 1.76 rejects Nimbus's first setup step for iCloud because no Apple ID has been given yet. Nimbus now goes straight to asking for your Apple ID and password, then shows a page for the verification code Apple sends to your devices (type `sms` there to get it by text message instead). The Apple ID field is no longer masked, and masked fields have a button to show what you typed. ([#162](https://github.com/CasaVargas/Nimbus/issues/162))
- **Finder hid the last ".xxx" of every name in a Nimbus location.** A folder named `me@example.com` showed as `me@example`, and with "Show all filename extensions" off, files showed without their extensions. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#165](https://github.com/CasaVargas/Nimbus/pull/165))
- **Turning off "Show in Finder" for one cloud could break a download in progress from another.** Each cloud now keeps its in-progress downloads and thumbnails apart, and a failed or cancelled download no longer leaves its temporary file behind. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#163](https://github.com/CasaVargas/Nimbus/issues/163), [#164](https://github.com/CasaVargas/Nimbus/pull/164))
- **Files with long names, especially in Chinese, Japanese or Korean, could fail to open from Finder.** Nimbus added to the name while downloading and pushed it past the 255-byte limit. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#159](https://github.com/CasaVargas/Nimbus/pull/159))
- **Dropping a file onto the Nimbus window did nothing.** Files and folders dragged in from Finder now open Send to Nimbus with the cloud and folder on screen already filled in; if a name is already taken you are asked whether to replace it or keep both. ([#139](https://github.com/CasaVargas/Nimbus/issues/139))
- **The file list did not update after a transfer.** When an upload or a copy between clouds finishes, the folder on screen now refreshes by itself.

## For contributors

- `Nimbus/Local.xcconfig` can now set your own team prefix and bundle IDs, so a build signed with your team gets working Finder integration without editing tracked files. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#161](https://github.com/CasaVargas/Nimbus/pull/161))

Everything new in 1.5 is described in [the 1.5.0 release notes](https://github.com/CasaVargas/Nimbus/releases/tag/v1.5.0).

## Known issues

- Files dropped at the top level of a Backblaze B2, S3 or similar cloud fail in Transfers: they have to go inside a bucket.
- Sharing more than 2 GB of items that have to be copied first (photos from Photos, files inside another app's own storage) is refused with a message. Use Services > Send to Nimbus… in Finder for those.
- After you set up your own Google sign-in, Google shows "Google hasn't verified this app" when you sign in. That is expected for an ID you made yourself: choose Advanced, then continue.
- On a Google Drive cloud still using the shared sign-in, choosing a folder in a sheet and Send to Nimbus's check for existing names can still time out after 30 seconds. Try again, or set up your own sign-in.
- Some Google Docs, Sheets and Slides files show an enormous size in Finder. Nothing is downloaded; the size just isn't known until the file is exported.
- After quitting Nimbus in the middle of a backup, the next run can fail once on a leftover temporary file. Run it again and it completes.
- A backup started by hand and cut off by quitting is not marked as stopped; its row still shows the previous run.
