Finder no longer overwrites files that changed on the server, renamed folders keep their contents, and deleting a top-level folder of a combine remote can no longer wipe the cloud behind it. Thanks to [Mike Grupenhoff (@mgrupenhoff)](https://github.com/mgrupenhoff), who found, fixed and tested four of the changes in this release.

## Requirements

- macOS 15 or later, Apple silicon or Intel
- rclone. If none is installed, Nimbus offers to download the official build for your Mac and checks it before use. Share links and backup previews need rclone 1.76 or later.

## Install

From 1.1.0 or later: choose Nimbus > Check for Updates…, or wait for the automatic check if you turned it on.

With Homebrew: `brew trust --tap casavargas/tap && brew tap CasaVargas/tap && brew install --cask nimbus`, or `brew upgrade --cask nimbus` if you installed it that way.

From 1.0.1 or earlier: open the DMG, drag Nimbus to Applications, launch it. The app is signed with a Developer ID certificate and notarized by Apple, so Gatekeeper opens it without warnings. Nothing to redo.

## Fixed

- **Deleting a top-level folder of a combine remote deleted everything in that cloud.** A combine remote's top-level folders are the clouds it combines, so deleting `gdrive` inside one emptied the whole Google Drive. Nimbus no longer offers Rename, Delete or New Folder at that level, in Finder or in the Nimbus window, and refuses them if asked anyway. Everything inside those folders works as before. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#188](https://github.com/CasaVargas/Nimbus/issues/188), [#189](https://github.com/CasaVargas/Nimbus/pull/189))
- **Finder overwrote files and folders that had changed on the server.** An edit saved on this Mac replaced an edit made on another device, and a new or renamed file or folder replaced, or was merged into, one with the same name on the server. Now the server's copy is kept: your edit is saved next to it as `name (conflicted copy <date>).ext`, and a new or renamed item takes the next free name, such as `report 2.pdf`. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#184](https://github.com/CasaVargas/Nimbus/issues/184), [#185](https://github.com/CasaVargas/Nimbus/pull/185))
- **A folder renamed or moved in Finder showed empty, and deleting it deleted its files.** The files were still on the server, but Finder never listed them under the new name. Finder now shows them right after the move. Files you had downloaded in that folder show as not downloaded and download again when opened. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#186](https://github.com/CasaVargas/Nimbus/issues/186), [#187](https://github.com/CasaVargas/Nimbus/pull/187))
- **Renaming or deleting a big folder in Finder could stop halfway.** On S3, Backblaze B2 and similar clouds, a rename that took over 30 seconds was cut off and restarted, and one taking more than about two and a half minutes failed, leaving the files split between the old and new names. These now run to the end, and Finder shows their progress. Errors that can't go away, such as deleting a file already deleted on the server, no longer retry for ten seconds first. Thanks to [@mgrupenhoff](https://github.com/mgrupenhoff). ([#180](https://github.com/CasaVargas/Nimbus/issues/180), [#181](https://github.com/CasaVargas/Nimbus/pull/181))
- **The folder picker for copies and syncs doubled the path when you opened a folder inside another**, so `BACKUP/RAW 2025` became `BACKUP/BACKUP/RAW 2025` and failed. Thanks to [@ysengrin101](https://github.com/ysengrin101) for the report. ([#182](https://github.com/CasaVargas/Nimbus/issues/182), [#183](https://github.com/CasaVargas/Nimbus/pull/183))
- **Settings… in the menu bar opened behind other apps** when Nimbus ran from the menu bar only. It now comes to the front. ([#193](https://github.com/CasaVargas/Nimbus/pull/193))
- The Nimbus window now shows an error when a delete, rename or new folder fails, instead of doing nothing. ([#189](https://github.com/CasaVargas/Nimbus/pull/189))

Everything new in 1.5 is described in [the 1.5.0 release notes](https://github.com/CasaVargas/Nimbus/releases/tag/v1.5.0).

## Known issues

- A server edit that keeps the file's modification date isn't seen as a change, and an edit made on the server while this Mac is uploading the same file is still replaced by this Mac's.
- Files dropped at the top level of a Backblaze B2, S3 or similar cloud fail in Transfers: they have to go inside a bucket.
- Sharing more than 2 GB of items that have to be copied first (photos from Photos, files inside another app's own storage) is refused with a message. Use Services > Send to Nimbus… in Finder for those.
- After you set up your own Google sign-in, Google shows "Google hasn't verified this app" when you sign in. That is expected for an ID you made yourself: choose Advanced, then continue.
- On a Google Drive cloud still using the shared sign-in, choosing a folder in a sheet and Send to Nimbus's check for existing names can still time out after 30 seconds. Try again, or set up your own sign-in.
- After quitting Nimbus in the middle of a backup, the next run can fail once on a leftover temporary file. Run it again and it completes.
- A backup started by hand and cut off by quitting is not marked as stopped; its row still shows the previous run.
