# Backups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saved backup jobs (cloud or Mac folder → cloud or Mac folder) with a required dry-run preview, versions through `--backup-dir`, a removal limit, an in-app schedule with catch-up, and run history through `TransferStore`.

**Architecture:** One pure builder (`BackupRequest`) turns a `BackupJob` into an RcloneKit `SyncRequest` for both the preview (`DryRun` + report flags) and the real run. `BackupStore` persists jobs to `backups-v1.json`; `BackupRunner` queues runs on the existing daemon and records them as `.backup` transfers; `BackupScheduler` (phase 2) plans runs from a pure planner with an injected clock. Copy Between Clouds shares the endpoint type, the location picker and the preview sheet.

**Tech Stack:** Swift 6, SwiftUI (macOS 15), RcloneKit, Swift Testing, rclone 1.76 RC API.

**Spec:** `docs/superpowers/specs/2026-11-08-backups-design.md`

## Global Constraints

- No `.system(size:)`. No new SPM dependencies. Colors, spacing, radius, typography and motion through `DesignSystem` tokens.
- View models and stores are `@Observable @MainActor`. Services that talk to rclone take a protocol, not `RcloneClient`, so tests use a mock (the pattern of `RemoteProbeClient`/`MockRcloneClient`).
- RcloneKit tests assert on the **captured request body**, never only on a mock that answers anything.
- Jobs file: `~/Library/Application Support/Nimbus/backups-v1.json`, `{ "version": 1, "jobs": [...] }`, pretty-printed, sorted keys, atomic write.
- Versions folder inside the destination is `.nimbus-versions`; its exclude rule is exactly `/.nimbus-versions/**`; run stamp format `yyyy-MM-dd HHmmss` in the Mac's time zone.
- Preview report flags: `missingOnDst`, `differ`, `error` always; `missingOnSrc` only for mirror. Never `match` or `combined`.
- `MaxDelete` only for mirror jobs. `DryRun` only for previews.
- A job runs only when `approvedFingerprint == job.fingerprint`. Nothing bypasses this, including Back Up Now.
- UI copy is taken verbatim from the spec's Screens section. No "remote", "rclone", "sync" or "mount" in user-facing strings except **Copy rclone Command**.
- After adding files: `cd Nimbus && xcodegen generate`, then `git checkout -- Nimbus/FileProviderExtension/Info.plist`.
- Tests: `xcodebuild test -project Nimbus/Nimbus.xcodeproj -scheme Nimbus -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO` (or XcodeBuildMCP `test_macos` with those `extraArgs`). RcloneKit: `cd RcloneKit && swift test`. Only one `xcodebuild` at a time on this Mac.
- Never launch a dev build with a demo `RCLONE_CONFIG` on a Mac that has real Nimbus File Provider domains (`cleanupStaleDomains` removes them).
- One PR per phase, on its own `feat/backups-phaseN` branch from `main`.

## Review Focus

1. **A mirror whose source folder becomes empty** (external drive mounted but empty, a cloud folder emptied): expect the removal limit to stop the run and a "stopped" notification, not a wiped destination. Test in Task 4 (`MaxDelete` present for mirror) and Task 8 (`limitHit` outcome from rclone's "failed to delete" error).
2. **A source path that no longer exists** (unplugged drive, renamed folder): expect a failed run with "directory not found" rewritten as "The source folder isn't available. Is the drive connected?", and no removals. Test in Task 8.
3. **Editing a job's excludes or destination after approval:** expect the job to stop running until previewed again, while a rename or schedule change keeps the approval. Test in Task 3 (fingerprint) and Task 8 (runner refuses).
4. **A path with spaces, quotes or non-ASCII** (`~/Documents/Résumé "final"`): expect the RC body to carry it raw and the CLI string to quote it so it pastes into zsh correctly. Test in Task 4.
5. **A history file written by this build read by a 0.9.x build:** expect the old build to leave it untouched (unsupported version), not quarantine it as corrupt. Test in Task 6 (`version: 2` written once a `.backup` record exists; v1 still loads).
